## Project Overview

Infynii is an AI-powered search mobile app. Users ask questions via a chat interface, LangGraph agents search the web (Tavily API) and summarize results (Google Gemini 2.5 Flash), streaming responses back in real-time via NDJSON.

## Monorepo Structure

- **pnpm workspaces** + **Nx** for build orchestration
- `apps/infynii` — React Native mobile app (Expo 52, React Native 0.76)
- `apps/hono-api` — Backend API (Hono 4.7, Node.js)
- `packages/shared` — Shared TypeScript types (`@jpvnk/infynii-shared`)

## Build & Dev Commands

```bash
pnpm install              # Install all dependencies
pnpm build                # Build all packages (shared must build first)
pnpm api:dev              # Start Hono API with hot reload (port 8787)
pnpm api:build            # Build API for production
pnpm app:dev              # Start Expo dev server
pnpm app:dev:ios          # Run on iOS simulator
pnpm app:dev:android      # Run on Android emulator
pnpm gentypes             # Regenerate Supabase types into packages/shared/src/db-schema.ts
```

Individual app commands (run from their directories):
```bash
# apps/hono-api
pnpm dev                  # tsx watch src/index.ts
pnpm build                # tsc
pnpm start                # node dist/index.js

# apps/infynii
pnpm dev                  # expo start
pnpm ios                  # expo start --ios
pnpm android              # expo start --android
```

**Important:** Nx `dev` targets depend on `^build`, so shared packages build automatically before dev starts.

## Architecture

### Backend (`apps/hono-api`)

- **Entry:** `src/index.ts` → Hono server on port 8787
- **Routes:** `src/router.ts` — All API routes under `/api/v1`
- **Agents:** LangGraph state machines in `src/agents/`
  - `search/` — Evaluates query, searches via Tavily, scores/filters results (threshold 0.5), retries up to 3 times
  - `summarize/` — Generates AI summaries of search results using Gemini
- **Streaming:** POST `/api/v1/stream` returns NDJSON (newline-delimited JSON)
- **LLM:** Google Gemini 2.5 Flash, temperature 0, no retries
- **Database:** Supabase (PostgreSQL). LangGraph checkpoints stored in postgres.
- **Validation:** Zod schemas with `@hono/zod-validator`

### Mobile App (`apps/infynii`)

- **Navigation:** Expo Router (file-based) in `app/` directory with tab layout in `app/(tabs)/`
- **Screens:** `screens/ChatScreen.tsx` (main chat), `screens/SearchResultScreen.tsx` (detail view)
- **API Client:** Hono RPC client provided via `context/HonoProvider.tsx`
- **NDJSON Parsing:** `helpers/ndjson.ts` — `processNDJSONResponse()` parses streaming responses
- **Path alias:** `@/*` maps to project root (configured in tsconfig)

### Shared Package (`packages/shared`)

- Two export paths: `@jpvnk/infynii-shared` (client-safe types) and `@jpvnk/infynii-shared/server` (LangGraph state — backend only)
- `db-schema.ts` is auto-generated by `pnpm gentypes` — do not edit manually
- ESM module system (`"type": "module"`)

## TypeScript

- Strict mode enabled across all packages
- Backend uses `NodeNext` module resolution with `.js` extensions in imports
- Mobile app extends `expo/tsconfig.base`
- Backend JSX configured for Hono (`jsxImportSource: "hono/jsx"`)

## Environment Variables

Backend requires (see `apps/hono-api/.env.example`):
- `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
- `GOOGLE_API_KEY` (Gemini)
- `TAVILY_API_KEY`

## Code Conventions

- Functional components with hooks (no class components)
- camelCase for variables/functions, PascalCase for components
- Lowercase hyphenated directory names
- Avoid `any` — use precise types
- Minimize `useEffect` and `useState`; use `React.memo()` for static-prop components
- Use `StyleSheet.create()` for React Native styling
- Use `expo-router` for navigation (not React Navigation directly)
- Optimize FlatLists with `removeClippedSubviews`, `maxToRenderPerBatch`, `windowSize`

## Git Workflow

- Main branch: `main`, development branch: `devel`
- Feature branches branch off `devel`, PRs target `devel`
- Package manager: pnpm 10.4.0
- Do not add `Co-Authored-By` lines to commit messages
- Commit message prefixes: `feat:` for new features, `fix:` for bug fixes, `chore:` for config/cleanup changes
- First word after prefix must be capitalized (e.g. `feat: Add search results streaming`)
